# Infinia Store 全站 UI 实现方案

> 交付对象：负责实现的 AI / 前端开发者。本文是实现规格，不包含本轮代码改动。
> 基线：2026-09-12 工作区内当前 React 源码；包含尚未提交的修改。以当前文件为准，不能回退到早期 Vue 版本或此前对话中的旧页面结构。
> 核查方式：读取路由、页面 JSX、状态处理、公共样式与相关测试清单；未逐页面登录浏览器实测。文中的“现状”指代码可确认的结构与状态，视觉效果和交互完成度仍需实现阶段浏览器验证。

## 1. 目标、范围与不可变项

将 Aceternity 风格的中性面板、细边框、柔和高光、统一控件和微交互扩展至 `store-web` 全部 15 个路由页面，以及管理控制台的 9 个分区。保留蜂巢主题与现有 Infinia 品牌图标，覆盖浅色、深色、中文、英文、移动端及业务状态。

### 必须保留

- **品牌图标原文件 `store-web/public/infinia-logo.svg` 不改形状、不换色、不加滤镜重绘。** 顶栏、登录页、页脚继续引用 `/infinia-logo.svg`；新增品牌位置也复用此文件。对话预览中的金色六边形 Logo 不采用。
- 现有图标自身蓝紫色可以保留；暖金是界面交互与蜂巢装饰色，两者并存。不要为统一色调把产品图标也染成金色。
- 品牌名称与现有代码一致，使用 **Infinia Store**。
- 保留现有路由、角色权限、登录回跳、支付跳转、制品类型、发布与审核状态、下载安全流程、会员等级计算和 API 合约。
- 保留 `infinia.store.theme` 持久化键及用户已保存的主题。当前默认浅色且 `enableSystem=false`，本轮不因深色预览擅自更改默认主题策略。
- 保留现有等级语义及 `bee-levels.ts`、`BeeLevelBadge` 的等级差异，不把所有等级都改成相同金色。
- 当前库、发布中心已有结构重构，应在此基础上完善。不要重新实现已经存在的四标签制品库与管理/发布分离。

### 范围边界

- 包含 `App.tsx`、`router.tsx` 的呈现状态、`RouteContent`、所有 `views/*.tsx`、共享组件和中英文文案。
- `/status` 在 Store 内的跳转页属于本轮；其指向的独立 `monitor-web` 不属于本轮。
- `website`、后端管理接口、Java 服务、支付网关页面不属于视觉迁移范围。
- 不新增批量更新、一键安装、自动保存、支付成功、后台安全校验等现有数据/接口不支持的能力。需要补齐的本地错误、重试、忙碌状态可实现，但必须标明状态来源。
- 不提交重置工作区、删除既有修改、重新脚手架化项目等操作。

## 2. 当前工程与设计基线

| 项目 | 当前情况 | 实现要求 |
| --- | --- | --- |
| 框架 | React + Vite + TypeScript | 不迁移 Next.js；Aceternity 示例中的 Next 专用引用需要适配 |
| 样式 | Tailwind v4，`styles/main.css`，部分语义 token + 局部 Slate 覆盖 | 统一为语义 token；不能只替换蓝色变量而遗漏局部背景/文字 |
| 交互 | Motion、Radix、next-themes、React Router | 复用已有依赖；新控件保持键盘、焦点和路由语义 |
| 组件 | `components/magicui`、`MagicCard`、`ShimmerButton`、公共 `.btn/.input/.card` | 应用层建立统一入口，逐页迁移；未迁移完不直接删除旧组件 |

| 主题 | token 的深色定义与大量 `dark:bg-slate-*` 混用 | 以 token 决定明暗层次，避免局部“蓝黑色拼块” |
| 制品库 | 已有四标签、搜索、类型筛选、可更新优先、坐标复制 | 延续结构，完善列表对齐、数据状态和组件语言 |
| 发布中心 | 已有管理首页、导入/手动创建、产品上下文三步流程和摘要栏 | 延续流程，明确本地文件状态与服务端提交/扫描的边界 |
| 管理控制台 | 已有分组侧栏，实际 9 个 tab | 保留分组结构，统一各分区密度与操作反馈 |

## 3. 统一设计系统

### 3.1 颜色与层次

以下是拟定 token；可在视觉验证中小幅调整，但所有调整通过 token 完成。普通正文对比度至少 4.5:1，关键非文本控件与焦点至少 3:1。

| Token / 语义 | 深色 | 浅色 | 用途 |
| --- | --- | --- | --- |
| canvas | `#09090B` | `#FAF9F6` | 页面背景 |
| surface | `#141416` | `#FFFFFF` | 卡片、列表、表单面板 |
| surface-raised | `#1C1C20` | `#FFFFFF` | 弹层、菜单、悬浮区域 |
| surface-muted | `#101013` | `#F3F1EC` | 输入底色、表头、静态图标底座 |
| text-primary | `#FAFAFA` | `#18181B` | 标题、正文 |
| text-secondary | `#A1A1AA` | `#62626C` | 次级说明 |
| border-subtle | `#29292D` | `#E5E2DB` | 面板分界 |
| border-control | `#64646E` | `#86818A` | 需要明确辨识的输入/选择控件边界 |
| brand-solid | `#F6BD60` | `#EAB04B` | 主按钮背景，文字固定深色 |
| brand-text | `#F6BD60` | `#885400` | 选中态、品牌链接、重点说明 |
| info | `#93C5FD` | `#1D4ED8` | 正在扫描/上传/审核等信息状态 |
| success | `#86D69B` | `#18733D` | 已成功、已发布、已验证 |
| warning | `#F3C46D` | `#8A5500` | 需要处理、待支付、可更新 |
| danger | `#FCA5A5` | `#B42332` | 失败、驳回、破坏性操作 |

- 金色主按钮使用深色文字，禁止沿用 `bg-accent text-white` 导致对比度不足。
- **品牌色与业务信息色分离**：原先 `badgeToneClass.accent` 同时用于选中与流水线状态，迁移时拆为 brand/info，不能把所有扫描状态改成金色。
- 面板边框可以很淡；输入框、复选框和焦点边界需要更清晰，不能全站都使用同一个低对比边框。
- 顶栏深色为接近 canvas 的中性黑，浅色为半透明暖白；当前近黑常驻顶栏改为随主题变化，品牌图标保持原样。

### 3.2 布局、尺寸与文字

- 标准 PageShell 上限 1200px（现有 75rem），左右内边距：桌面 24px、移动端 16px。顶栏、页头、主内容、页脚同一对齐基线。
- 宽数据页面也先使用 1200px 外层；表格在自身容器横向滚动，不让整页撑出屏幕。不要让管理页突然恢复 1440px 页面外边界。
- 页面顶部间距 32px，区块间距 24–32px，面板内边距 24px，字段间距 16px，标签到字段 8px。
- 普通页标题 28px/36px，移动端 24px/32px；区块标题 18px/28px；正文与控件 14px/22px；辅助文字 12px/18px。首页展示标题可增至 40–48px。
- 继承现有系统字体栈，中文 PingFang SC / Microsoft YaHei；不额外依赖在线字体。版本、校验和、坐标使用等宽字体。
- 控件圆角 10–12px，面板 16px，状态徽标胶囊；避免同页任意混用 4/8/12/24px 圆角。
- 普通按钮与输入高 44px；桌面紧凑行操作高 36px；移动端可点击目标至少 44px。不要对所有 `a` 或所有 `button` 全局强设高度。
- 表单单列阅读宽度约 640–720px。复杂发布布局：160px 步骤栏 + 自适应主区 + 260–280px 摘要；仅在 ≥1200px 展开三列，1024–1199px 改为顶部步骤 + 双列，窄屏单列。

### 3.3 蜂巢与动效

- 原品牌 Logo 与蜂巢背景是两个独立元素；蜂巢不得替换 Logo。
- 首页/登录页可有较完整的蜂巢背景；常规页面仅在标题区右侧显示渐隐细线；管理表格、账户密码区、支付状态区不铺花纹。
- 上传区允许低透明蜂巢，文字与文件卡片必须使用足够实的底色。空状态可使用现有 BeeCrest / HexCluster 的简化静态版本。
- 金色微光只在聚焦/悬停激活；不让每个面板持续发光。普通状态切换 150–220ms；标签选中底板可 200–250ms 平滑移动。
- 管理页不采用卡片倾斜、磁吸按钮、模糊邻卡、文字逐字出现或持续粒子动画。
- `prefers-reduced-motion` 下关闭光效位移、呼吸和非必要出场动画；忙碌信息仍以文字呈现。

### 3.4 Aceternity 组件选型

参考的是选定的一组组件语言，不是把演示库全部混入业务。优先使用官方免费组件；不引入需购买的模板块。

| 应用层组件 | 参考 | 实现约束 |
| --- | --- | --- |
| Button | [Tailwind CSS Buttons](https://ui.aceternity.com/components/tailwindcss-buttons)、[Stateful Button](https://ui.aceternity.com/components/stateful-button) | 统一 primary/secondary/ghost/danger，pending 由业务 Promise 驱动；无演示用定时成功 |
| AccentAction | [Hover Border Gradient](https://ui.aceternity.com/components/hover-border-gradient) | 只用于少量页级入口，品牌色可配置；避免装饰层拦截点击 |
| Input / Textarea | [Signup Form](https://ui.aceternity.com/components/signup-form) | 固定 label，聚焦柔光，支持 error/disabled/readOnly；不使用会消失的输入文案 |
| Tabs | [Tabs](https://ui.aceternity.com/components/tabs) | 只借鉴选中底板移动；不使用后台内容卡片堆叠/缩放，完整实现 tab 键盘语义 |
| UploadField | [File Upload](https://ui.aceternity.com/components/file-upload) | 支持拖拽、键盘、文件替换及真实错误；文件类型按业务入口配置 |
| Surface | [Card Spotlight](https://ui.aceternity.com/components/card-spotlight) | 普通表格/表单面板默认静态；展示卡可选弱 spotlight |
| Select / Checkbox / Dialog / Dropdown | 现有 Radix 基础 + 同套视觉 token | 保留 Portal、焦点管理和原生语义；不为视觉相似重写不完整控件 |

所有新组件必须适配 Vite、当前 Tailwind v4 和已有 Motion 版本；官方代码先核对许可与依赖，再在应用层封装。此方案不要求更改 vendored 原组件源码。

## 5. 全局壳层和路由状态

### App.tsx

现状：常规页顶栏/页脚；`/signin` 独立全屏。顶部含按角色显示的发现、浏览、库、发布、审核、管理，桌面搜索，语言、主题和用户菜单；窄屏导航横向滚动且有边缘提示。

实施：保留导航结构与角色规则；顶栏约 64–72px，主题化底色和轻微磨砂。当前项用中性选中底板 + 金色标记，避免只有文字变粗。搜索/主题/语言/头像按钮统一尺寸。窄屏保留所有可用入口，搜索需可展开，菜单保留账户、库、组织、发布、管理和退出。

页脚继续使用真实现有链接。**不得照抄预览图添加未实现的帮助/隐私/条款链接，或写死“所有系统运行正常”**；现有状态入口继续导航 `/status`。

### router.tsx / RouteContent.tsx

- 保留所有现有 RequireAuth 角色规则：库/账户/会员/组织需登录；发布允许 PUBLISHER、ORG_ADMIN、REVIEWER、PLATFORM_ADMIN；审核允许 REVIEWER、PLATFORM_ADMIN；管理仅 PLATFORM_ADMIN。
- `auth.ready=false` 当前直接返回空；补充中性会话加载骨架，防止白屏，不提前展示敏感数据。
- 未登录仍带原目标跳转 `/signin?redirect=...`；无角色仍按当前规则返回首页，不能借视觉重构改变授权逻辑。
- lazy chunk 加载、渲染失败分别有加载说明、错误与刷新按钮。保留 pathname 变化重置错误边界及刷新保留 query/hash 的逻辑。

## 6. 逐页面实现规格

### 6.1 发现页 `/` — DiscoverView.tsx

**现状**：展示区含蜂巢/渐变文字、搜索与指标；下方类型入口、精选卡片、最新卡片。精选区域有 loading/error 分支，最新区域直接渲染列表。

**改造**：保留展示区，但缩减多色渐变和持续数字动画。现有 Logo 不变；标题用主文字色，重点词可暖金。类型入口采用一致的中性按钮，精选/最新共用 ListingCard。首页允许最明显的蜂巢主题，其余页递减。

**状态要求**：首次加载卡片骨架；请求失败保留搜索与类型入口并提供重试；精选/最新分别有空数据说明，不渲染空白标题；计数未取得时用骨架/占位，禁止冒充真实 0。推荐/精选标记须由已有字段决定。

### 6.2 浏览页 `/browse` — BrowseView.tsx

**现状**：独立搜索栏、APP/PLUGIN/SKILL/MCP/FLOW 类型筛选、排序、三列卡片；从 URL 初始化 q/type；请求错误、加载、空结果；nextCursor 存在时追加加载。

**改造**：统一页头与搜索工具栏；类型改选中底板式 Tabs，排序改统一 SelectMenu。与首页共用卡片，不改变为带大装饰图的营销卡。

**状态要求**：区分首次加载与追加加载；追加时保留已显示内容并禁用重复请求。无结果提供“清除筛选”；失败保留 query/type/sort。现有追加按钮文案偏“查看全部”，应改为准确的“加载更多”。验收同路由搜索和浏览器前进/后退是否同步 URL 与视图，现有仅挂载初始化行为不能被新 UI 掩盖。

### 6.3 产品详情 `/listing/:namespace/:slug` — ListingDetailView.tsx

**现状**：产品页头、类型/等级/版本/指标、安装或下载 CTA、收藏；包含 overview、versions、permissions、dependencies、compatibility、security、reviews 七个内容区，安装确认、举报弹窗与发布者等级门槛编辑。区分上游聚合制品及平台/架构产物。

**改造**：页头突出真实产品图标、名称、摘要和一个主下载/安装动作；收藏/举报为次级动作。Tabs 与制品库统一。概要采用正文 + 信息栏，版本/依赖/安全区域使用清晰数据面板，用户评价采用统一列表。原 ShimmerButton 迁移至统一状态按钮。

**必须覆盖**：

- 加载、请求失败、等级不足门禁；门禁继续展示升级/登录所需入口，不能把受限内容提前渲染。
- 安装阶段 `idle → resolving → confirm → downloading → verifying → done / failed`，保留依赖确认及失败阶段的准确原因。
- 主安装动作与 APP 平台下载按现有分支保留；版本列表中的下载按 release/artifact 独立 loading/error，失败可重试。
- 上游聚合数据的未知版本、按需生成包、缺失大小/校验和使用真实回退文案，不能显示“0 B”“0.0.0”“已验证”假信息。
- 无版本、无依赖、无评价、元数据缺失提供对应空态；缺少安全数据不等同扫描通过。
- 权限页保留实际声明的权限与说明；兼容性页保留平台/架构/宿主等已有矩阵及上游来源说明。没有声明不等于不需要权限，缺少兼容数据不等于全部平台兼容；移动端矩阵可在局部横向滚动。
- 评分选择/未评分禁用提交、登录与未登录、评价提交结果；举报编辑/提交失败/成功；门槛编辑保存中/失败。
- 弹窗有焦点圈定、Esc/取消、关闭后归还焦点，错误保留用户填写内容。

### 6.4 制品库 `/library` — LibraryView.tsx

**当前已经实现**：installed/favorites/entitlements/history 四标签，名称回退、坐标复制、搜索、类型筛选、更新优先、仅看更新；无更新轻提示；收藏/权益列表及安装历史表。

**重要：真实时序与预览图的差异**

当前 `uploadAndSubmit()` 在最终确认才执行：创建上传会话 → `putRaw` 上传文件 → `/submit` → `pollStatus()`。第二步只是选择文件；不能把 AI 概念图当作业务流程。

1. 第一步“版本信息”：创建/恢复真实版本草稿。仅 API 成功后可显示“版本草稿已创建”，不显示未实现的“自动保存”。
2. 第二步建议标题改为“选择安装包”：显示本地文件名、大小与确实执行过的 manifest 解析结果；进入确认前文案为“已选择，待上传”。已有历史 findings 标为上次结果。
3. 第三步“确认并提交”：展示真实版本、渠道、兼容性、包信息，主动作“上传并提交审核”。点击后才显示“正在上传/正在提交”。
4. 服务端进入 SCANNING 后显示“安全扫描中”；进入 IN_REVIEW 显示“等待审核”；PUBLISHED 才显示“已发布”。如存在 QUARANTINED/REJECTED/CHANGES_REQUESTED，显示具体状态与允许动作。
5. 超出本轮有限轮询后仍在处理中，明确“仍在处理中”，提供刷新状态；不强行跳成功，不把超时直接视为发布失败。

**状态矩阵**：

| 状态 | UI / 可用动作 |
| --- | --- |
| 产品/版本加载中或失败 | 列表/表单骨架、局部重试；不当作暂无版本 |
| 无组织、无产品、暂无版本 | 对应创建引导，避免三个完整空面板同时堆叠 |
| 包解析成功/失败 | 字段来源说明/可读错误；失败可替换文件，保留手动内容 |
| DRAFT | 版本草稿、选择包、确认并提交 |
| UPLOADING / SCANNING | 状态反馈、阻止重复提交；不展示提前通过的检查项 |
| IN_REVIEW | 等待审核、查看状态，不能继续上传 |
| CHANGES_REQUESTED / REJECTED | 原反馈可见，允许按现有返工机制重新上传 |
| PUBLISHED | 发布成功、进入产品详情；不可用发布者删除替代撤回 |
| DEPRECATED / YANKED / QUARANTINED | 历史/限制态，显示状态与说明，保留原有操作限制 |
| 删除/提交失败 | 对应对象内错误与重试，保留上下文和文件信息 |

上传许可沿用 `DRAFT/REJECTED/CHANGES_REQUESTED`；删除许可沿用当前逻辑，禁止删除 `PUBLISHED/DEPRECATED/YANKED/QUARANTINED`。不要仅按 UI 步骤号推导服务端操作权限。

## 7. 跨页面业务状态规则

| 场景 | 统一呈现 | 禁止事项 |
| --- | --- | --- |
| 首次加载 | 与目标内容一致的 skeleton + 可读加载文本 | 所有页面都显示卡片网格；未加载显示 0 |
| 刷新/追加 | 保留已有内容，当前按钮 pending | 全页闪白、重复提交 |
| 空数据 | 当前区域一个空态，提供真实下一步 | 整页堆多个相同虚线框 |
| 无匹配 | 保留搜索/筛选，清除筛选按钮 | 当作用户从未创建/安装过 |
| 请求失败 | 就地错误/重试，保留填写和上下文 | 转为空列表或成功提示 |
| 业务处理中 | 状态来自真实请求/枚举，适时允许刷新 | 定时器自动成功、假百分比 |
| 操作成功 | 当前对象短提示，必要时更新依赖区 | 订单创建=已支付；提交审核=已发布 |
| 危险操作 | danger 色 + 对象和后果 + 保留现有确认 | 用金色营销按钮诱导点击 |
| 权限不足 | 保留路由/服务端鉴权，解释不可操作原因 | 隐藏按钮即视为已授权 |
| 未知枚举/字段 | 可读原值或“—”，缺失与零区别 | 渲染空白徽标、编造兼容版本/计数 |

预览图中示例产品、数量、页码、日志和状态不能写进正式页面。分页只在已有全量本地集合或游标接口上实现；没有总数就不显示假页数。

## 8. 响应式、可访问性与表单行为

- 验证 390、768、1024、1440px；390px 无整页横向滚动，数据表只在自己的容器内滚动。
- 桌面三列布局在 1024px 已降级，不能给步骤、表单、摘要同时分配固定宽度造成挤压。
- 移动端产品操作和表单主按钮不被 sticky footer/键盘挡住；页面底部预留真实操作栏高度和 safe area。
- Tabs/菜单完整键盘操作；输入具备 label、错误通过 aria-describedby 关联；图标按钮有 aria-label；状态信息使用合适的 aria-live，避免大量重复朗读。
- Dialog 焦点圈定与归还、Escape/取消行为；警告和错误不只依赖颜色。
- 长中文名称、长英文按钮、长坐标/版本、空值、999+ 数量必须可布局。英文界面不继承只适合中文的固定按钮宽度。
- 禁用需说明原因，不仅降低透明度。提交中保留按钮宽度；页面切换、标签切换不要无意清空草稿。
- 若需要防止离开未提交表单，区分已有服务端草稿和只在内存中的文件；不得暗示浏览器刷新后还能恢复本地 File。

## 9. 实施顺序与交付边界

### 阶段 A：基线与公共组件

1. 开始实施前再次读取 git diff、当前路由与本文件对应页面；其他 AI 可能仍在修改工作区，不覆盖他人修改。
2. 保存原 Logo 校验值，截图记录当前页面浅深主题；使用本地测试数据，不操作真实付款、发布、撤回等业务来验证视觉。
3. 建立 token、PageShell、Button/Input/Select/Tabs/Surface/UploadField/ResultPanel 统一语言。
4. 建立开发专用组件状态预览：normal/hover/focus/disabled/pending/error/success，使用真实组件而非另写一套 CSS。
5. 更新壳层与公共状态，使旧样式入口也跟随 token；保留可逐页回归的兼容层。

### 阶段 B：优先业务页

依次迁移制品库、发布中心、产品详情。先核对实际状态，再调整视觉；特别落实上传/提交时序、安装流程与等级门禁。完成这三页的浅深/中英文/窄屏后再扩展。

### 阶段 C：商城与个人页

迁移首页、浏览、账户、会员、会员结果、组织；复用已验证的列表、表单、状态面板。组织与会员结果的缺失错误/超时反馈一并补齐。

### 阶段 D：运营与系统页

迁移审核、管理九分区、登录/注册、回调、状态跳转、404、路由错误。运营表单采用低动效密度，保留所有确认和权限语义。

### 阶段 E：收敛与验收

逐页清理没有用途的色值/旧组件引用，检查 `dark:bg-slate-*`、旧主色、独立 ShimmerButton、未主题化表单。通过所有页面后再删除无引用旧代码，不以全局正则替换作为迁移方法。

## 10. 验收与测试清单

### 静态/自动化

- 在 `store-web` 使用仓库现有包管理器运行 `typecheck`、`test`、`build`；这些是实现阶段要求，本方案生成阶段未运行应用测试。
- 保留并运行现有 `components`、`bee-level`、`listing-download`、`membership-view`、`membership-result`、`admin-membership`、`admin-upstreams`、`user-center`、`route-content`、`status-redirect`、`session-login`、`i18n` 等测试。
- 针对新改变的真实行为增加测试：库双数据源失败不呈现空态；收藏类型筛选；发布选择文件不显示已上传；轮询超限；组织切换过期响应；审核重复提交与确认；回调网络异常。
- 不新增仅断言颜色 class 的大批脆弱单测。交互断言以角色/标签/可访问名称为主，保留现有必要 testid。
- 确认原 Logo 文件内容未改变；中英文 key 完整，theme storage key 与默认策略不变。

### 浏览器与视觉

- 全部 15 个路由 + 管理 9 个分区，浅色/深色至少各一轮；重点页补齐中英文与 390/768/1024/1440px。
- 游客、普通用户、发布者、组织管理员、审核员、平台管理员按当前角色可见性验证。
- 截图至少覆盖：库正常/无匹配/请求失败；发布管理/创建/三个步骤/返工/处理中；详情门禁/安装确认/下载失败；会员购买禁用/结果超时；管理长表/同步日志弹窗；登录校验/注册/回调失败；404。
- 确认弹窗、下拉菜单未被面板 overflow 裁切，sticky 区域不覆盖内容，键盘焦点可见。
- 页面之间保持统一标题左边界、控件尺寸、面板色和状态含义；蜂巢不影响表格阅读。
- 检查 reduced motion、长文案、缺失图标、未知状态、慢请求；无新增控制台错误。
